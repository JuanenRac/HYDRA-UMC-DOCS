### ステータス

JSON スキーマ v1 コントラクト、有効/無効なフィクスチャ、Python 検証クライアント、
ホスト側のテスト、そして HYDRA-UMC-SERVER 自身の HTTP サーフェスに対する実際の
最初の OpenAPI v1 スライス（`contracts/openapi/v1/server.openapi.json` -
[docs/CONTRACTS.md](docs/CONTRACTS.md#openapi-v1) 参照）が実装されています。
Protobuf の公開はその後の互換性マイルストーンです。Go、TypeScript、Rust のクライアントはすでにあります。

実際に動作する自動互換性マトリクス（`tools/verify_contract_matrix.py`）は、公開されているすべてのスキーマを Python バリデータ自身のコントラクト一覧と突き合わせて検証します。これにより、`project-manifest.schema.json`（このエコシステムの各リポジトリが公開する `hydra-umc.project.json` のコントラクト）にバリデータのエントリが一つも存在しないという実際のギャップを発見し、修正しました。現在では、各適合フィクスチャがそのファイル名どおりに判定されること、さらに未知のコントラクトおよび非互換なスキーマバージョンのケースについても正しく判定されることを証明しています。

下記の最初のマイルストーン以降、さらにコントラクトが追加されました(現在18件)。外部マシン連携のための公開コントラクト `BridgeJob`/`GateDecision`(詳細は [docs/BRIDGE_CONTRACT.md](docs/BRIDGE_CONTRACT.md))は `HYDRA-UMC-BRIDGE-ROS2`/`-OPENPNP`/`-PRINTER3D`/`-CNC`/`-LASER`/`-AMR`/`-DROIDS`/`-UAV` で共有され、独自の実データJSONワイヤー形式(`job_to_dict()`/`job_from_dict()`/`decision_to_dict()`)を持ちます。加えて、リクエスト側が主張する状態の代わりにゲートが使う、ブリッジ自身が観測した機器の状態と、保持メッセージを無視し同じ冪等キーを二度実行しないジョブ受付（`JobIntake`/`IdempotencyStore`）があります。`ScenarioOutcome` コントラクトと `compare_runs()` は、共有の「本当に直ったか」チェックで、障害が再現しなくなってもベースのフィンガープリントが変わっていなければ `apparent-success`(`regression-fixed` ではなく)を返します。`Operation` コントラクトと `validate_status_transition()` は、共有の目標/ジョブ/操作ライフサイクル - `received`/`authorized`/`queued`/`sent`/`confirmed`/`terminated`/`rejected` を表し、単一の「実行済み」の器にまとめることは決してありません。`Operation` のオプション `result` と `concludes_success()` は、実際の証拠(`run_id`/`origin`/`observers_enabled`/`outcome`)により、古い/再送された結果や観測が無効化された実行から成功を結論づけることを拒否します。独立した `Capability` コントラクトと `is_capability_usable()` は、あるターゲットが操作 `kind` のサポートを*宣言している*かどうかを、その裏付けが*最近実際に検証された*かどうか(`last_checked_at_utc`/`checked_configuration`/`max_age_seconds`)とは別のデータとしてモデル化し、宣言されただけで一度も検証されていない、または古くなった能力が黙って利用可能と扱われることを防ぎます。また `hydra-umc-sdk-mock-server`(`mock_server.py`)は、実際のCM5・ロボット・MCUハードウェアが無くてもUIやアダプタを開発できるよう、既知の各コントラクトについて有効なサンプルペイロードを単純なHTTP経由で提供します。10個すべてのコントラクトが、上記の互換性マトリクスで検証済みの有効・無効な適合フィクスチャを少なくとも1つずつ持っています。

### ルートの単一ソース、メッセージング契約、強化できるブリッジ転送

- **サーバーのルート群の単一ソース（パイロット：接続ルート）：** `contracts/sources/connections.routes.json` が、閉じたスキーマ `ConnectionClient` と `ConnectionEvent` の上に `GET /api/connections/clients` と `GET /api/connections/events`（アクセス、ステータスコード、クエリパラメーター）を宣言し、`python tools/contract_source.py` がそこから `contracts/openapi/v1/server.connections.openapi.json` を生成します。生成物が古い、同梱のスキーマのコピーが違う、サーバーのルートや列挙がソースからずれている場合、`--check` は失敗します。[`docs/CONTRACT_SOURCE.md`](docs/CONTRACT_SOURCE.md) を参照してください。
- **メッセージング契約：** `MqttPublish` は `qos`（0、1、2）を運び、`ProductionEvent` は終わった 1 サイクル（`source_id`、`at_utc`、`good`、`cycle_time_s`）を表し、生産レポートが OEE に変換します。
- **パイロットの後にサーバーが追加したルートと型付き契約：** `contracts/openapi/v1/server.full.openapi.json` は `GET /api/ecosystem/health`、`GET /api/robots/liveness`、`POST /api/robot/{id}/heartbeat`、`POST /api/stop-all/release`、接続のルート、公開の `GET /health` を載せ、型付きの部分は最初の 4 つを記述します。新しい閉じた契約 2 つ、`EcosystemHealth`（各サービスの状態・理由コード・バージョンのずれとサーバー証明書の状態）と `RobotLiveness`（各ロボットの live・stale・unknown）は Python クライアントが検証し、Go・Rust・TypeScript のクライアントにハッシュ、フィクスチャ、差分テスト付きで取り込まれています。[`docs/CONTRACTS.md`](docs/CONTRACTS.md) を参照してください。
- **強化できるブリッジ転送（制限はすべて既定でオフ）：** `MessageDispatcher(..., max_queue=N, max_payload_bytes=N)` は実行中のコマンドの後ろで待つコマンドを制限し（最も古いものを破棄して数えます）、大きすぎるペイロードを拒否します。停止レーンは制限されず、停止の動詞は上限の対象外です。`stats()` は `dropped`、`oversized`、`queued` のカウンターを返します。`connect_with_retry` と `open_bridge_client` は最初の接続にジッター付きの指数的な待ちを取り、`reconnect_min_delay_seconds` / `reconnect_max_delay_seconds` で MQTT クライアントの再接続遅延を設定します。[`docs/PYTHON_CLIENT.md`](docs/PYTHON_CLIENT.md) を参照してください。
