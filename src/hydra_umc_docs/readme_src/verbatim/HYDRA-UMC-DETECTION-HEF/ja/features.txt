* ✅ **実装済み v0 —— モデルレジストリ：** `registry.py` はコンパイル済みモデルの JSON レジストリを解析・スキーマ検証し、重複した名前+バージョンのエントリを検出し、名前/タスクに対する最新バージョンを検索し、ローカルの `.hef` ファイルをレジストリと照合して sha256 チェックサムを検証します。下記の `registry validate`/`registry latest`/`registry add` から利用可能で、実行にもテストにも Hailo SDK やハードウェアは不要です。
* 🔒 **実装済み v0 —— 安全なロードのゲート：** `compatibility.py` の `safe_load()` は、チェックサムを検証する前に実際の Hailo アーキテクチャ互換性(`hailo8`/`hailo15h` など——各レジストリエントリは今やターゲットチップを宣言します)を検証し、両方の実際のチェックが通った場合にのみモデルをデプロイ準備完了として報告します。下記の `registry load` から利用可能です。
* 🌐 **実装済み v0 —— JSON/HTTP API：** `api.py` の `serve` サブコマンドは、同じレジストリ/安全なロードのチェックを長時間稼働するローカルサービス(デフォルト `127.0.0.1:8093`)として実行し、`GET /registry`、`GET /registry/latest`、`GET /registry/load`、`GET /stats` を公開します——レジストリとモデルディレクトリは起動時に一度だけ設定され、リクエストごとではありません。各エンドポイントの実際にキャプチャされた例は [`docs/CLI_REFERENCE.md`](docs/CLI_REFERENCE.md) を参照してください。
* 🛠️ **産業用検知（計画中）：** PCB 部品、はんだ接合部、機械的欠陥を対象としたモデル。
* 📐 **フィデューシャルアライメント（計画中）：** ピック＆プレース同期のための高精度アンカー。
* ⚡ **量子化パフォーマンス（計画中）：** Hailo-8/Hailo-10 NPU を対象としたサブ 10ms 推論のための INT8/INT4 バリアント。*（将来の作業——この環境にはまだない実際の Hailo-8/Hailo-10 NPU と Dataflow Compiler が必要です。）*
* 🤖 **姿勢推定（計画中）：** ロボットアームの関節追跡のためのキーポイント検出。*（同じ理由で将来の作業です。）*
* 🧩 **独立したプロジェクトとして存在する理由：** モデルのコンパイルとバージョン管理はデータ/ML ワークフローであり、それらを提供するランタイムプロセスとは完全に異なります——ツールチェーンをここに保つことで、不良なコンパイルが実行中の知覚ノードを危険にさらすことは決してなく、モデルは [HYDRA-UMC-VISION-NODE](https://github.com/JuanenRac/HYDRA-UMC-VISION-NODE) に到達する前にオフラインで反復・検証できます。
* 📐 **入出力の取り決め(任意):** レジストリの項目には `io_contract` を付けられます。モデルへの入力のしかた(レイアウト、色順、データ型、正規化、リサイズまたはレターボックス、パディング値)と、出力の読み方(NMS の形式、ボックスの順序、正規化されたボックス、しきい値)を示します。レジストリの読み込み時に検証され、レジストリを書き直しても保たれ、そのチェックサムはモデルの識別情報に含まれます。付いていない項目はこれまでどおり読み込まれます。
* 📐 **契約は新しいモデルでは必須、読み込み時は任意：** `registry add` には `io_contract` ファイル（または明示的な `--no-io-contract`）が必要です。`--require-io-contract` を付けると、契約のないエントリはレジストリ読み込み時にエラーとなり、ロードも拒否されます（既定でオフなので古いレジストリは引き続き読み込めます）。エントリには `channel`（`stable` または `canary`）もあり、ノードは読み込んだモデルを `POST /models/loaded`（既定でオフ）に報告してレジストリの判定を受け取れます。
* 🎯 **コンパイル後の精度（ゲートは既定でオフ）：** `registry record-accuracy` はコンパイル済みモデルの検出結果と正解ボックスから mAP@0.5 を測定し、量子化前のモデルのスコアと並べて記録します。`--min-accuracy-ratio` は精度が落ちすぎたモデルや未測定のモデルを拒否します。検出結果の生成にはアクセラレーターが必要で、ここでは行いません。
* 📦 **無線更新のための署名付きバンドル（既定でオフ）：** `registry make-bundle` は署名済みレジストリと `.hef` をまとめます。`registry apply-bundle` は何かを書き込む前にすべてのハッシュ、署名、バージョンを検証し、公開鍵と明示的なスイッチを必要とし、直前のレジストリを保持してロールバックできます。ノードへのバンドル配信はアップデーターの役割で、まだ接続されていません。
* 📨 **SDK 契約の検出結果：** `decoder.detection_frame` はデコードした検出結果を、ビジョンノードや安全・サーボのサービスが読む `DetectionFrame` メッセージ（ピクセルまたは正規化した角座標のボックス、フレーム、撮影時刻、モデルの識別情報）に変換します。従来の `Detection.as_dict` は変更ありません。
* 🔐 **検証済みバイト列:** `safe_load(..., keep_bytes=True)` はファイルを一度だけ読み、SHA-256 を確認して、そのバイト列をそのまま返します。これらからモデルを組み立てる側(ビジョンストリーマーとビジュアルサーボ API がそうします)は、確認後に変わったファイルを渡されることがありません。`GET /stats` は絶対パスではなくファイル名を示します(`serve --stats-full-paths` を付けた場合を除く)。
* 🩺 **統一された `GET /health`（既定では閉じています）：** `serve --health-open`（または `HYDRA_UMC_DETECTION_HEF_HEALTH_OPEN=1`）を指定すると、サービスは `GET /health` に `{"status": "ok", "service": ..., "version": ...}` で応答します。ファミリーのすべてのサービスで同じ本文です。スイッチがなければ、ルートは存在しないルートと同じく `404` を返します。ループバック以外の呼び出し元はサービスのベアラートークンが必要で、本文にはパス・設定・秘密情報は含まれません。
* 🪪 **HYDRA-UMC-SERVER の ID（既定ではオフ）:** `serve --identity-key-file FILE`（または `HYDRA_UMC_DETECTION_HEF_IDENTITY_KEY_FILE=FILE`）を指定すると、サービスは自身のトークンに加えて、サーバーがログイン時に発行する署名付きトークンを受け付けます。閲覧者は読み取りだけで変更はできず、資格情報のないリクエストはループバックでも拒否されます。スイッチがなければ何も変わりません。

**正直な現状確認 —— 今日実際に動くもの：** 本プロジェクトの仕事のうち、実際にハードウェアに依存しない半分——モデルレジストリ（`registry.py`）と実際の安全なロードのゲート（`compatibility.py`）——は、`registry validate`/`registry latest`/`registry load`、および長時間稼働する JSON/HTTP API としての `serve`（`api.py`）を通じて公開され、実装され、テストされています（{tests} 個のテスト）。このレジストリが記述するモデルを実際に*生成*する ONNX エクスポート、Hailo Dataflow Compiler による量子化、HAR/HEF パッケージングは、依然として将来の作業です：いずれもこの環境にはない実際の Hailo ハードウェアを必要とします。

* 🔀 **サービス稼働中に読み込み済みモデルの報告をオン・オフする（既定はオフ）:** `serve --settings-file FILE`（または `HYDRA_UMC_DETECTION_HEF_SETTINGS_FILE=FILE`）で小さなJSONファイル `{"acceptLoadedReports": true}` を指定します。HYDRA-UMC-SERVER がこれを書き込み、サービスは変更されると再読み込みするため、`--accept-loaded-reports` の切り替えに再起動は不要です。ファイルがなければ起動時の指定が有効で、信頼できないファイルは報告をオフにし、トークンまたはSERVERのIDなしにループバック以外で報告をオンにすることはできません。オフにすると、それまでの報告は破棄されます。
