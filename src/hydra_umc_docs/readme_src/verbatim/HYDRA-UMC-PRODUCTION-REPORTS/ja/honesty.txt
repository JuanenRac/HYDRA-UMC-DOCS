**正直な現状確認 - 実際に今動くもの:** 本物のOEE計算式（`oee.py`）、テレメトリの欠落から算出する本物の稼働率計算（`availability.py`）、HYDRA-UMC-DATALAKE自身の `GET /query` への本物のHTTPクライアント（`datalake_client.py`）、シフト/日境界に関する唯一の信頼できる情報源で、真夜中をまたぐ実際の夜勤も含む（`shift.py`）、バイト単位で再現可能なCSVエクスポート（`export.py`)、そしてこれらすべてを公開する本物のHTTP API（`api.py`: `GET /reports/oee`、`/reports/availability`、`/reports/{oee,availability}/export`、`/stats`）は本物であり、テスト済みです（122件のテスト、`pytest`）。以下の「主な機能」にあたかもすでに動いているかのように記載されているものの、実際には実装されていないもの: このコードのどこにもPDFエクスポートは存在せず（`export.py` が書き出すのはCSVと自己完結型のHTMLページだけです）、日次/週次/月次レポートのスケジューリングもなく、管理者に何かを「送信」するメール/配信の仕組みもありません - すべてのレポートはリクエストごとに、HTTP呼び出し1回につき正確に1回だけ、その場でライブに計算されます。ジョブディスパッチャーは完了したサイクルを `ProductionEvent` メッセージとして引き渡せます（`POST /events/production`、既定ではオフ）。この経路は、実際のディスパッチャーのコードと偽の DATALAKE を使って計算機上でのみ検証されており、実際の生産ラインでは一度も検証されていません。これまでに実際に出荷されたものの詳細は `CHANGELOG.md` を、残っている未完了事項は下記のROADMAPを参照してください。

> **安全性とセキュリティの現状:** このエコシステムは認証された安全システムではありません。ハードウェアの E-STOP 経路、ファームウェアが強制する制限やインターロック、検証済みの動作コマンドはまだありません。ファームウェアイメージは CRC-32 と Ed25519 署名で検査し、リリースビルドは公開済みの開発用鍵を拒否します(リレーの先のツールヘッドと拡張ボードは引き続き URTC のブートローダーを使い、署名ではなく共有鍵の HMAC-SHA256 を使います)。TLS と相互 TLS は任意で、既定では無効です。独自基板はまだ実装も試験もされていません。ここに書かれた内容を人の安全のために頼る前に、[セキュリティベースライン](https://github.com/JuanenRac/HYDRA-UMC-DOCS/blob/main/docs/SECURITY_BASELINE.md)と[脅威モデル](https://github.com/JuanenRac/HYDRA-UMC-DOCS/blob/main/docs/THREAT_MODEL.md)をお読みください。
