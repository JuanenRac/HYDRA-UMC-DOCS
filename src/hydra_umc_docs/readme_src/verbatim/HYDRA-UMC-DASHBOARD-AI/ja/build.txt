Node.js >= 20 が必要です。

```bash
# Linux/macOS
./dev.sh      # 依存関係をインストールし、:5174 で Vite 開発サーバーを起動します
./build.sh    # 依存関係をインストールし、実際のテストスイートを実行し、バージョンを増加させ、型チェックを行い、dist/ をビルドします

# Windows
dev.bat
build.bat
```

`npm run build` は `tsc --noEmit && vite build` を連鎖的に実行します——バージョンを変更することはないため、壊れたビルドが増加したバージョン番号を出荷することは決してありません。`npm run dev`
はポート `5174` で Vite を起動します（HYDRA-UMC-STUDIO 自身の `5173`
とは別のポートのため、両方を同時に並行して実行できます）。`npm test`
は実際の Vitest スイートを直接実行します。

デフォルトでは、2つの実際のパネルは同一オリジンのパス `/api/datalake` と
`/api/anomaly` を呼び出します。`scripts/serve_static.py`（および Vite 開発
サーバー）がこれらを `127.0.0.1:8095` の HYDRA-UMC-DATALAKE と
`127.0.0.1:8097` の HYDRA-UMC-ANOMALY-DETECTOR に転送します（どちらの
サービスも CORS ヘッダーを送らないため、ブラウザから直接は呼び出せません）
——`VITE_DATALAKE_URL`/
`VITE_ANOMALY_URL`（`vite build`/`vite dev` の前に設定、Vite がビルド時
にインライン化します）で上書きして、別のデプロイ先を指すことができます。

HYDRA-UMC-SERVER の背後では、このページは `/dashboard-ai` で配信されます（このリポジトリが隣にチェックアウトされていれば、HYDRA-UMC-SERVER の `build-frontend` がビルドしてコピーします）。そこでは、同じブラウザーで HYDRA-UMC-STUDIO にサインインした人のアクセストークン（トークンは同一オリジンのアドレスにのみ送られます）を使い、そのサーバーのリレー `/api/ai/datalake`（読み取り専用）と `/api/ai/anomaly-detector` を通して読み取ります。そのためサーバーのロールが適用され、各サービスは自分の Bearer トークンをサーバーだけに保ちます。拒否されたセッションはパネルに表示されます（STUDIO からサインインしてください。管理者またはオペレーターが必要です）。ダッシュボードがそこにあれば、HYDRA-UMC-ANOMALY-DETECTOR を `HYDRA_UMC_ANOMALY_PROTECT_READS=1` で起動できます。

`scripts/serve_static.py` はすべての応答に Content-Security-Policy を付けます。スクリプトはページ自身からのみ(インラインスクリプトとプラグインは不可)、フレームへの埋め込みは不可、接続先はページ自身のオリジンのみです。`VITE_DATALAKE_URL`/`VITE_ANOMALY_URL` を使うビルドでは、呼び出すオリジンを `--connect-src オリジン`(複数指定可)で追加します。`--csp off`(または `HYDRA_DASHBOARD_CSP=off`)はポリシーを送らず、前段のプロキシが設定する場合向けです。それ以外の `--csp` の値は完全なポリシーとしてそのまま使われます。`npm run lint` は ESLint(推奨ルール、typescript-eslint、React フックのルール)を実行し、CI では型チェックとテストと並んで実行されます。 スタンドアロンモードでは、同じスクリプトが、トークンを求めるサービスの Bearer トークン(`HYDRA_UMC_DATALAKE_READ_TOKEN`、なければ `HYDRA_UMC_DATALAKE_TOKEN`、および `HYDRA_UMC_ANOMALY_TOKEN`。いずれも `..._FILE` として、1 行目がトークンのファイルでも指定可能)を提示するため、ページがトークンを持つことはありません。トークンはダッシュボードが行う呼び出し(データレイクの読み取り、検出器の状態、ウィンドウの採点)でのみ送られます。ベースラインの適合、データレイクへの書き込みや保持期間の操作はトークンなしで送られ、サービスに拒否されます。ループバック以外のアドレスに bind したサーバーは、`--allow-tokens-off-loopback` を指定しない限り、トークン付きでは起動しません。

これらのブラウザから見える URL を設定する前、または実際の AI プロバイダーを
接続する前に、[`docs/SECURITY.md`](docs/SECURITY.md) を読んでください。レスポンス
検証、コンテンツ安全性、失敗時の動作、および秘密情報を含めないルールを定義しています。

すべての実際のトレンドサマリーの取得は、実際の AI プロバイダーゲートも
実行します。実際のプロバイダーが設定されていない場合(v0 の正直な
デフォルト)、パネルは実際の統計的フォールバックを、はっきりとラベル
付けして表示します：

```ts
import { safeGenerateNarrative, NO_PROVIDER_CONFIGURED } from './lib/aiProvider'

const narrative = await safeGenerateNarrative(NO_PROVIDER_CONFIGURED, { sourceId, kind, field, summary })
// { narrative: "robot-1/motor_temp/value: 4 sample(s), ranging 10.00 to 50.00,
//    averaging 29.00, latest 36.00 (rising).", generatedBy: 'statistical-fallback' }
```

エラーを投げる、または `narrative` が欠落/不正なレスポンスを返す
プロバイダーは、パネルをクラッシュさせたり何も表示しなかったりする
代わりに、まさにこの実際のフォールバックに降格します。
