* 🧾 **Official VDA 5050 schemas and a configurable hold:** the tests check every message the bridge builds against the official VDA 5050 2.0.0 JSON schemas (`order` and `instantActions`, vendored in `tests/vda5050_schemas`); an instant action now carries `actionName` next to `actionType`, because the official instantActions schema asks for it. `AmrCoordinator(abort_action=AmrCoordinator.START_PAUSE)` makes the abort phase hold the vehicle with `startPause` instead of dropping its order with `cancelOrder` (the default); both are always forwarded. `MOVE_TO_HOME` goes through the same gate as every movement. `AmrCoordinator.resume()` sends `stopPause` only for a READY cell and a vehicle read as paused, and `abort_action=AmrCoordinator.ABORT_BOTH` sends `cancelOrder` and then `startPause`. *(implemented)*
* ✅ **Real, hand-checkable coordinate-frame transform:** `FrameTransform` maps a factory-frame `(x, y)` into a specific AMR's own local frame given that AMR's real origin/heading on the factory floor - verified with an identity case, a pure translation, a 90-degree heading rotation and a real round-trip test. *(implemented, tested in `tests/test_coordinator.py`)*
* ✅ **Real, VDA-5050-inspired order-action vocabulary, on the real two-channel split:** `MOVE_TO_STAGING`, `PICK_LOAD`, `MOVE_TO_DESTINATION`, `DROP_LOAD`, `MOVE_TO_HOME` publish on the real VDA 5050 `order` topic (queued, part of a route); `CANCEL_ORDER` publishes on the real, separate `instantActions` topic (immediate, bypasses the order queue) - matching VDA 5050's own real `cancelOrder` action name AND its own real channel, checked against the [official schemas](https://github.com/VDA5050/VDA5050/tree/main/json_schemas). *(implemented)*
* ✅ **Real per-action coordinate validation:** a movement action missing `x`/`y`, or carrying a non-numeric one, is rejected locally before the transform ever runs. *(implemented, tested)*
* ✅ **Real shared safety gate:** every job dispatched through `AmrCoordinator.dispatch()` is evaluated by `evaluate_job()` from `HYDRA-UMC-SDK`'s `bridge_contract`, the same gate every sibling bridge and HYDRA-UMC-SERVER use; a productive phase requires an `IDLE` external machine and a `READY` HYDRA-UMC cell, while `CANCEL_ORDER` remains requestable during a fault. *(implemented)*
* ✅ **Fail-closed phase routing and static evidence:** an unknown future SDK phase is denied. `inspect_order_plan.py` emits the static schema `1.1` order plan (real `actions`/`instant_actions` channel split) without opening any transport. *(implemented, tested)*
* ✅ **Real VDA 5050 MQTT publisher:** `mqtt_transport.py`'s `Vda5050Publisher` sends an already-gated dispatch as a real, spec-shaped message on the correct real topic (`{interfaceName}/{majorVersion}/{manufacturer}/{serialNumber}/{order|instantActions}`) - a rejected dispatch never reaches the network. *(implemented, tested in `tests/test_mqtt_transport.py`)*
* ✅ **Non-mutating build/test:** `build-test.bat`/`.sh` compile the source and run deterministic unit tests without changing version or CHANGELOG. *(implemented, see BUILD & RUN below)*
* 🔜 **A vendor-specific fleet-manager REST/WebSocket adapter** (for a fleet platform that isn't VDA 5050-native) - introduced only after that platform is selected and tested. *(planned)*
* ✅ **Observed machine state and order ids that survive a restart:** `AmrCoordinator.dispatch()` accepts the state the fleet manager reported for the vehicle, which the shared gate uses instead of the `machine_state` written in the job (a message anybody on the broker may publish); `Vda5050Publisher` gives each order an `orderId` with a token of its own, so that a restart that counts `headerId` from the beginning again does not reuse the id of an earlier order (VDA 5050 refuses it). *(implemented, tested in `tests/test_observed_and_order_ids.py`)*
* ✅ **VDA 5050 names on the wire, a client the broker accepts and an observer that listens:** the internal `CANCEL_ORDER` / `PICK_LOAD` / `DROP_LOAD` go out as the case-sensitive VDA 5050 action types `cancelOrder` / `pick` / `drop` (before, `CANCEL_ORDER` went out as it is, which an AGV does not recognize as a cancel), and a movement is only its destination node, with no invented action type; `actionId` and `nodeId` carry the session token like the `orderId`; `header_id` and `timestamp_iso` can be left out (the publisher counts per topic and stamps UTC) and are validated when given; a coordinate that overflows, a non-finite number or a point outside `FrameTransform.bounds` is refused (`allow_nan=False`). `open_mqtt_client()` takes a `client_id` (the broker authenticates by its prefix), uses callback API v2 and waits for the broker's answer instead of returning a client that cannot publish; with a `Vda5050Observer` it subscribes to the AGV's `state` and `connection` topics and derives the machine state the gate uses (OFFLINE when stale, not ONLINE or not in AUTOMATIC mode; otherwise SAFE_STOP, FAULT, HOLDING, RUNNING or IDLE). *(implemented, tested against fakes and the emulator; never run against a real AGV or fleet manager, and without a plant graph a job still becomes a single-destination-node order, which a real AGV may refuse; with a graph see the route bullet below)*
* ✅ **Follows the global stop (off by default):** with `HYDRA_UMC_AMR_GLOBAL_STOP=1` the bridge reads the retained announcement of the server on `hydra/swarm/safety/estop`; while it says `SAFE_STOP`, or cannot be read, it refuses with a reason: every order that moves the vehicle (a cancel and a pause pass). Stops and read-only requests keep working and only `READY` ends the refusal. *(implemented, tested against a real broker; never run with a real server)*
* 🗺️ **A route on the plant graph, one multi-node order (off unless a graph file is given):** with `HYDRA_UMC_AMR_PLANT_GRAPH` pointing to a JSON file of nodes, directed edges and optional zones, a job with `goal_node` is planned from the node the vehicle last reported (`lastNodeId`) to that node with the shortest route and published as ONE VDA 5050 order with every node and edge, through the same gate and the same global stop as any movement; an unknown last node, an unknown goal or no route is refused. `plant_graph.py`. *(implemented, tested against fakes; never run against a real AGV)*
* 📊 **The state of the vehicle for the data lake and for OPC UA (off by default):** with `HYDRA_UMC_AMR_PUBLISH_STATE=1` the bridge publishes the battery, errors, position and machine state of the vehicle on `hydra/bridges/amr/state`, which the telemetry collector already reads into the data lake (and so the anomaly detector); with `HYDRA_UMC_AMR_PUBLISH_OPCUA=1` the same readings go as a typed, read-only list of nodes on `hydra/bridges/amr/opcua` for a gateway to show to a SCADA. A state that is unknown or stale publishes nothing. `state_report.py`. *(implemented, tested against fakes; the OPC UA server does not read that topic yet and nothing ran against a real AGV)*
* 🚧 **Zone interlock (off by default):** with `HYDRA_UMC_AMR_ZONE_INTERLOCK=1` and a plant graph whose nodes name their zone, a vehicle whose next node lies in an occupied zone gets `startPause`; when the zone is free the bridge sends `stopPause` through the gate, and only to a vehicle it paused itself. The occupancy is read from `hydra/safety/zones/occupied`; an occupancy that cannot be read counts as occupied unless `HYDRA_UMC_AMR_ZONE_UNKNOWN=ignore`. `zone_interlock.py`. *(implemented, tested against fakes; the safety service does not publish that topic yet and nothing ran against a real AGV)*
