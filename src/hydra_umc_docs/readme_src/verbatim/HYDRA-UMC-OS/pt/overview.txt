O HYDRA-UMC-OS é a camada de plataforma instalável para um nó CM5 do HYDRA-UMC. Está construído sobre o Raspberry Pi OS ARM64; não substitui o Linux, o kernel do Raspberry Pi, o systemd, o NetworkManager, a libcamera nem os SDK dos fabricantes.

A sua responsabilidade é fornecer um perfil de dispositivo HYDRA-UMC reproduzível: configuração, ciclo de vida dos serviços, identidade local, diagnósticos, imagem de marca visual e atualizações coordenadas dos componentes HYDRA-UMC.

**Verificação de honestidade - o que realmente funciona hoje:** o agente de dispositivo só de leitura (`agent/src/hydra_umc_os/agent.py`: `DeviceDescriptor`/`HealthReport`, verificações de temperatura/armazenamento/rede, carregamento de perfis de configuração) é real e testado ({tests} testes unitários, `agent/tests/test_agent.py`, `python -m unittest discover`). O `provisioning/preflight_cm5.py` está verificado como idempotente e sem efeitos secundários por um teste real que o executa duas vezes e compara a saída (`tools/verify_preflight_idempotent.py`) mais 5 verificações reais de caminhos negativos (`tools/verify_preflight_negative.py`); o mecanismo de cópia de segurança/restauro de `provisioning/rollback.py` está verificado por 8 verificações reais, incluindo um cenário genuíno de falha parcial (`tools/verify_rollback.py`); a máquina de estados de recurso em modo AP de `provisioning/wifi_provision.py` está verificada por 46 verificações reais contra um NetworkManager simulado, incluindo uma ida e volta HTTP real de ponta a ponta sobre um socket de loopback verdadeiro (`tools/verify_wifi_provision.py`) - nenhuma das três precisa de root nem de um CM5 físico para ser verificada. O que nada disto correu: hardware CM5 real. O `image-builder/` é só documentação (um README de notas de reprodutibilidade, ainda sem código de montagem de imagem); `packages/debian/` contém os scripts do responsável e o ficheiro de copyright do pacote `hydra-umc-platform-base`, que `tools/build_deb.py` constrói num `.deb` verdadeiro (Python puro, sem dpkg, os mesmos bytes de cada vez) e que `tools/verify_deb_package.py` volta a ler; não foi instalado numa CM5 real. Veja o `CHANGELOG.md` para saber exatamente o que já foi entregue, e `docs/CM5_SOFTWARE_READINESS.md` para a linha precisa entre o que está verificado aqui e o que ainda precisa de hardware físico.
