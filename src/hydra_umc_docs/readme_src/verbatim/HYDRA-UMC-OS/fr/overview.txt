HYDRA-UMC-OS est la couche de plate-forme installable pour un nœud HYDRA-UMC CM5.
Il est construit sur Raspberry Pi OS ARM64 ; il ne remplace pas Linux, le
Noyau Raspberry Pi, systemd, NetworkManager, libcamera ou SDK du fournisseur.

Sa responsabilité est de fournir un profil reproductible du dispositif HYDRA-UMC :
configuration, cycle de vie du service, identité locale, diagnostics,
la marque visuelle et les mises à jour coordonnées des composants HYDRA-UMC.

**Vérification d'honnêteté - ce qui fonctionne réellement aujourd'hui :** l'agent de dispositif en lecture seule (`agent/src/hydra_umc_os/agent.py` : `DeviceDescriptor`/`HealthReport`, vérifications de température/stockage/réseau, chargement du profil de configuration) est réel et testé ({tests} tests unitaires, `agent/tests/test_agent.py`, `python -m unittest discover`). `provisioning/preflight_cm5.py` est vérifié comme idempotent et sans effet de bord par un test réel qui l'exécute deux fois et compare la sortie (`tools/verify_preflight_idempotent.py`), plus 5 vérifications réelles de cas négatifs (`tools/verify_preflight_negative.py`) ; le mécanisme de sauvegarde/restauration de `provisioning/rollback.py` est vérifié par 8 vérifications réelles, y compris un scénario d'échec partiel authentique (`tools/verify_rollback.py`) ; la machine à états de repli en mode AP de `provisioning/wifi_provision.py` est vérifiée par 46 vérifications réelles contre un NetworkManager factice, dont un véritable aller-retour HTTP de bout en bout sur un socket loopback réel (`tools/verify_wifi_provision.py`) - aucune des trois n'a besoin des droits root ni d'une CM5 physique pour être vérifiée. Ce qui n'a jamais été testé : du matériel CM5 réel. `image-builder/` n'est que de la documentation (un README de notes de reproductibilité, pas encore de code d'assemblage d'image) ; `packages/debian/` contient les scripts du mainteneur et le fichier de copyright du paquet `hydra-umc-platform-base`, que `tools/build_deb.py` construit en un vrai `.deb` (Python pur, sans dpkg, les mêmes octets à chaque fois) et que `tools/verify_deb_package.py` relit ; il n'a pas été installé sur une vraie CM5. Voir `CHANGELOG.md` pour ce qui a déjà été livré exactement, et `docs/CM5_SOFTWARE_READINESS.md` pour la limite exacte entre ce qui est vérifié ici et ce qui nécessite encore du matériel physique.

**Un seul écran local à la fois :** le réglage `HYDRA_LOCAL_SCREEN` (`hdmi` par défaut, `dsi` ou `none` ; enregistré avec `provisioning/install_kiosk.sh --screen <valeur>` dans `/etc/hydra-umc/local-screen.conf`) décide qui possède `tty1` : le kiosque HDMI de ce dépôt, l'application de HYDRA-UMC-DSI ou personne, de sorte que les deux kiosques ne réclament jamais la console en même temps. Voir `docs/CM5_PROVISIONING.md`. Testé avec des simulations ; non exécuté sur un vrai CM5.
