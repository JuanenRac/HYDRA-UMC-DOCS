HYDRA-UMC-OS is the installable platform layer for a HYDRA-UMC CM5 node.
It is built on Raspberry Pi OS ARM64; it does not replace Linux, the
Raspberry Pi kernel, systemd, NetworkManager, libcamera, or vendor SDKs.

Its responsibility is to provide a reproducible HYDRA-UMC device profile:
configuration, service lifecycle, local identity, diagnostics, visual
branding, and coordinated updates for HYDRA-UMC components.

**Honesty check - what actually runs today:** the read-only device agent (`agent/src/hydra_umc_os/agent.py`: `DeviceDescriptor`/`HealthReport`, temperature/storage/network checks, config-profile loading) is real and tested ({tests} unit tests, `agent/tests/test_agent.py`, `python -m unittest discover`). `provisioning/preflight_cm5.py` is verified idempotent and side-effect-free by a real test that runs it twice and diffs the output (`tools/verify_preflight_idempotent.py`) plus 5 real negative-path checks (`tools/verify_preflight_negative.py`); `provisioning/rollback.py`'s backup/restore mechanism is verified by 8 real checks including a genuinely partial-failure scenario (`tools/verify_rollback.py`); `provisioning/wifi_provision.py`'s AP-mode fallback state machine is verified by 46 real checks against a fake NetworkManager, including one real end-to-end HTTP round-trip over an actual loopback socket (`tools/verify_wifi_provision.py`) - none of the three needs root or a physical CM5 to verify. What none of this has been run against: real CM5 hardware. `image-builder/` is documentation only (a reproducibility-notes README, no image-assembly code yet); `packages/debian/` holds the maintainer scripts and the copyright file of the `hydra-umc-platform-base` package, which `tools/build_deb.py` builds into a real `.deb` (plain Python, no dpkg needed, the same bytes every time) and `tools/verify_deb_package.py` reads back; it has not been installed on a real CM5. See `CHANGELOG.md` for exactly what has shipped so far, and `docs/CM5_SOFTWARE_READINESS.md` for the precise line between what is verified here and what still needs physical hardware.

**One local screen at a time:** the setting `HYDRA_LOCAL_SCREEN` (`hdmi` by default, `dsi` or `none`; saved with `provisioning/install_kiosk.sh --screen <value>` in `/etc/hydra-umc/local-screen.conf`) decides who owns `tty1`: the HDMI kiosk of this repository, the app of HYDRA-UMC-DSI or nobody, so the two kiosks never claim the console together. See `docs/CM5_PROVISIONING.md`. Tested against stubs; it has not run on a real CM5.
