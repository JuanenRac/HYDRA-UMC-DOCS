HYDRA-UMC-OS es la capa de plataforma instalable para un nodo HYDRA-UMC CM5.
Está construido sobre Raspberry Pi OS ARM64; no reemplaza a Linux, el
kernel de Raspberry Pi, systemd, NetworkManager, libcamera o SDK de proveedores.

Su responsabilidad es proporcionar un perfil de dispositivo HYDRA-UMC reproducible:
configuración, ciclo de vida del servicio, identidad local, diagnóstico,
marca visual y actualizaciones coordinadas para los componentes de HYDRA-UMC.

**Verificación de honestidad - qué funciona de verdad hoy:** el agente de dispositivo de solo lectura (`agent/src/hydra_umc_os/agent.py`: `DeviceDescriptor`/`HealthReport`, comprobaciones de temperatura/almacenamiento/red, carga de perfil de configuración) es real y está probado ({tests} tests unitarios, `agent/tests/test_agent.py`, `python -m unittest discover`). `provisioning/preflight_cm5.py` está verificado como idempotente y sin efectos secundarios mediante un test real que lo ejecuta dos veces y compara la salida (`tools/verify_preflight_idempotent.py`), más 5 comprobaciones reales de rutas negativas (`tools/verify_preflight_negative.py`); el mecanismo de backup/restauración de `provisioning/rollback.py` está verificado por 8 comprobaciones reales, incluyendo un escenario genuino de fallo parcial (`tools/verify_rollback.py`); la máquina de estados de fallback en modo AP de `provisioning/wifi_provision.py` está verificada por 46 comprobaciones reales contra un NetworkManager falso, incluyendo un round-trip HTTP real de extremo a extremo sobre un socket loopback de verdad (`tools/verify_wifi_provision.py`) - ninguna de las tres necesita root ni una CM5 física para verificarse. Lo que nada de esto ha probado: hardware real de una CM5. `image-builder/` es solo documentación (un README de notas de reproducibilidad, sin código de ensamblaje de imagen todavía); `packages/debian/` contiene los scripts del mantenedor y el fichero de copyright del paquete `hydra-umc-platform-base`, que `tools/build_deb.py` construye como un `.deb` real (Python puro, sin dpkg, los mismos bytes cada vez) y que `tools/verify_deb_package.py` vuelve a leer; no se ha instalado en una CM5 real. Ver `CHANGELOG.md` para lo que ya se ha entregado exactamente, y `docs/CM5_SOFTWARE_READINESS.md` para la línea exacta entre lo que está verificado aquí y lo que todavía necesita hardware físico.
