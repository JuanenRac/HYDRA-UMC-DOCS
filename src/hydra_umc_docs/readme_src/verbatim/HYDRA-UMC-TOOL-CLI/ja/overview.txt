**HYDRA-UMC-TOOL-CLI** は、HYDRA-UMC エコシステムの開発者およびシステム
管理者向けの十徳ナイフです。HYDRA-UMC デプロイメントを照会、更新、
監査するためのコマンドラインツールを提供する、単一の静的な Go バイナリ
です。

長期的な目標は、ターミナルまたは CI/CD パイプラインから直接、大規模な
ミッションのデプロイ、並列ファームウェア更新（CAN-OTA）、そして詳細な
システム診断を行うことです。今日の時点では、他のすべての機能が基盤と
する実際に動作する基礎——バージョンレポートと HYDRA-UMC-SERVER に対する
ライブ HTTP クライアント——が提供されています。

### 主な機能：
* 🔏 **署名されたリリースバイナリ（`hydra-sign`）。** `go run ./src/cmd/hydra-sign sign --key 秘密鍵.pem ファイル...` は `ファイル.sha256`（`sha256sum` 形式）と `ファイル.sig`（ファイル内容に対する Ed25519 署名、base64）を書き出します。`verify --pub 公開鍵.pem ファイル...` は両方を検証し、公開鍵だけを必要とします。秘密鍵は指定されたファイルからのみ読み込まれ、表示もコピーもされません。`pubkey --key 秘密鍵.pem` は公開鍵の半分を表示します。テストにはテスト用に作った鍵を使います。どの鍵でリリースに署名するかはリリース手順が決めます。 リリース手順では、公開するすべてのバイナリに HYDRA のリリース鍵で署名し、`.sha256` と `.sig` を添付します。ビルドスクリプトは、バイナリが報告するバージョンをプロジェクトのマニフェストから設定します。
* ✅ **`hydra-cli version`** — CLI 自身の名前とバージョンを表示します。*（実装済み）*
* ✅ **`hydra-cli status [--server URL] [--config PATH]`** — 実行中の HYDRA-UMC-SERVER の `GET /api/hydra-info` を照会し、報告されたアイデンティティを表示します。*（実装済み）*
* ✅ **`hydra-cli robots [--server URL] [--config PATH] [--json]`** — 実行中の HYDRA-UMC-SERVER の `GET /api/settings` を照会し、実際のコントローラー/ロボット一覧（名前、オンライン状態、モデル、役割）を表示します。*（実装済み）*
* ✅ **`hydra-cli claims`、`claim <robot>`、`release <robot>`** — どのロボットを誰が予約しているかを一覧表示し（`GET /api/claims`）、ロボットの予約と解放を行います。予約はあなたのアカウントと、このプログラムのコントローラーID（`--controller-id`、`HYDRA_CLI_CONTROLLER_ID`、既定は `hydra-cli-<host>`）に属し、すべてのリクエストと一緒に送られます。拒否（別アカウント、別コントローラー、コントローラーID必須、ジョグ未アーム）は区別され、終了コード `8` で終わります。*（実装済み）*
* ✅ **`hydra-cli limits [--robot ID]`、`jog-arm <robot> <on|off>`、`jog <robot> <軸> <量> [--absolute]`** — サーバーが保持する安全上限を読み取り、ジョグのアーム/解除（サーバーが要求する場合のみ必要）と1軸の移動を行います。ロボットのモデルの上限を超えるステップは送信前に拒否され、上限を読めない場合は何も送られません。サーバーの警告も表示されます。*（実装済み）*
* ✅ **`hydra-cli robot <robot>`、`table <robot> <x> <y> [--rz N] [--relative]`、`audit [--limit N] [--type T] [--robot ID] [--verify] [--export FILE]`** — `robot` はロボット 1 台をリビジョン付きで読み取ります。`table` は XY テーブルを 1 回のアトミックなリクエストで動かします(送信前にモデルの上限と照合し、サーバーは全部適用するか何も適用しません)。`audit`(管理者のみ)は追記専用の監査記録を読み、受け取った行の SHA-256 ハッシュのチェーンを確認し(壊れていれば終了コード 8)、`--verify` ではサーバーに記録全体を確認させます。`--export FILE` は保存されているままの行を保存します。`claim`、`release`、`jog`、`table` は `--if-match REVISION`(または `current`)も受け付けます。そのリビジョン以降にロボットが変更されていれば、サーバーは終了コード 8 で書き込みを拒否し、何も適用されません。予約の WebSocket 通知は CLI では使いません(1 つのコマンドを実行して終了するため)。
* ✅ **`hydra-cli doctor [--server URL] [--config PATH] [--json]`** — 読み取り専用のサーバー契約診断：`/api/hydra-info` と `/api/settings` を検証し、公開されたコントローラー/ロボット数を一覧と照合します。コマンド送信やハードウェアの検査は行いません。`--json` を付けるとテキスト行の代わりに、チェックごとの `checkId`/`severity`/`status` を含む構造化レポートを出力します(スクリプト向け、詳細は [docs/DOCTOR.md](docs/DOCTOR.md))。*（実装済み）*
* 🔐 **セッション、安全な認証情報、フリート向けコマンド:** `login`/`logout` は自分だけが読めるファイルにセッションを保存します(実行のたびにログインしません)。パスワードやトークンは、`HYDRA_CLI_ALLOW_INSECURE=1` がない限り、他のマシンへの平文 http では拒否され、`HYDRA_CLI_CA_FILE` でプライベート CA を信頼できます。`scan`、`fleet doctor`、`stop`、`stop-all --yes`、`metrics`、`manifest validate` が追加されました。[`docs/CLI_REFERENCE.md`](docs/CLI_REFERENCE.md) を参照。
* 🧾 **`--json`、シェル補完、読み取り専用ビュー：** データを出力するすべてのコマンドは `--json` で JSON としても出力します（動作を行うコマンドでは `schema_version`、`command`、`ok` とコマンド固有のフィールドを持つ 1 つのオブジェクト。テキスト出力は既定のままで変わりません）。`completion <bash|zsh|fish|powershell>` はコマンド表から生成され、コマンド、サブコマンド、オプション、閉じた値を補完します。`connections`、`liveness`、`ecosystem-health` はサーバーからクライアントとサインイン履歴、各ロボットの生存信号、サービスの健全性を読み取り、`plan-simulate` はセマンティックプランナーのドライランでプランを検査します（何も実行されません。プランが拒否されると終了コード 8）。各応答は出力前に契約と照合され、形式が不正な応答は出力なしのエラーになります。[`docs/CLI_REFERENCE.md`](docs/CLI_REFERENCE.md) を参照してください。
* サーバーから届いて表示されるテキスト(エラーメッセージ、名前、バージョン)はすべて、共有の機密マスキングも通ります。応答に含まれるトークン、`password=` の値、bearer ヘッダーが端末に出ることはありません(他のプロジェクトと同じベクター)。
* ✅ **`hydra-cli completion <bash|zsh>`** — シェル用のタブ補完スクリプトを出力します。 *（実装済み）*
* ✅ **実際に安定した終了コード契約** — `0` 正常、`1` 一般エラー、`2` 使用方法エラー、`3` 設定エラー、`4` ネットワークエラー、`5` サーバーエラー、`6` 未実装、`7` 認証が必要、または拒否。各コマンドは単なる `exit 1` の代わりにこの契約を通じて自身の失敗を分類するため、この CLI をラップするスクリプトは*失敗の理由*に応じて分岐できます。*（実装済み）*
* ✅ **`hydra-cli config validate --config PATH`** — ローカルの設定ファイル（サーバー URL、リクエストタイムアウト）を読み込み、スキーマ検証します。*（実装済み）*
* ✅ **`hydra-cli config apply --config PATH [--dry-run]`** — `--dry-run` は実際の検証パスをエンドツーエンドで証明し、送信される内容を正確に表示します。指定しない場合は、実際にはまだライブのフリート書き込みエンドポイントが存在しないため、正直に「未実装」を返します。*（実装済み、dry-run のみ）*
* ✅ **`status`/`robots`/`doctor`/`shell` の `--config PATH`** — 同じ検証済みファイルの `server`/`timeoutSec` が、`config validate`/`apply` だけでなく、あらゆるライブコマンドの実際の HTTP 接続先とリクエストタイムアウトを左右するようになりました。両方指定された場合は引き続き `--server` が優先されます。*（実装済み）*
* ✅ **`hydra-cli shell [--server URL] [--config PATH]`** — 対話型 REPL:プロセスを再起動せずに、上記のいずれのコマンドも同じサーバーに対して繰り返し実行できます。単発実行と全く同じコマンドテーブルを介して処理されるため、シェルと単発実行の挙動が食い違うことはありません。`exit`/`quit`/Ctrl-D で終了。*（実装済み）*
* ✅ **`hydra-cli help` / `--help`** — 完全なコマンド使用方法。*（実装済み）*
* 🚧 **`hydra-cli deploy`** — ミッションと設定を複数のロボットに同時にアップロードします。*（計画中）*
* 🚧 **`hydra-cli flash-all`** — コントローラーと URTC ヘッド向けの並列ファームウェア更新。*（計画中）*
* 🚧 **`hydra-cli audit`** — CAN バスの健全性とセンサー検証のための自動診断スイート。*（計画中）*
