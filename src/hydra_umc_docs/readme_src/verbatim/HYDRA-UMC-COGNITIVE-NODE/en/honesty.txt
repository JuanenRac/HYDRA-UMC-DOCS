> **Honesty check - what actually runs today:** the family-readiness check and its versioned JSON schema (`family.py`, `manifest.py`, `models.py`) and the plain stdlib HTTP surface (`api.py`) are real and covered by {tests} passing tests (`pytest tests/` - `test_manifest.py`, `test_models.py`, `test_family.py`, `test_api.py`, `test_cli.py`). This node runs no model itself: "Local LLM Execution", "VLA Integration" and "Voice Command Processing" in the Key Features below are explicitly marked `(planned)` - there is no Hailo-10 runtime code in this repo. `docker-compose.yml` now references a real Dockerfile for all 4 children, but it has never actually been run as one stack in this dev environment (no Docker runtime available here) - each Dockerfile's command/port mapping was checked by hand against what each child's own systemd unit already runs on the real CM5, not verified live. See `CHANGELOG.md` for exactly what has shipped so far.


> **Safety and security status:** this ecosystem is not a certified safety system. There is no hardware E-STOP path, no firmware-enforced limits or interlocks and no verified motion command yet; firmware images are checked with CRC-32 and an Ed25519 signature, and a release build refuses the published development keys (the tool heads and expansion boards behind the relay still run URTC bootloaders, which take a shared-key HMAC-SHA256 instead of a signature); TLS and mutual TLS are optional and off by default; no custom board has been populated or tested yet. Read the [security baseline](https://github.com/JuanenRac/HYDRA-UMC-DOCS/blob/main/docs/SECURITY_BASELINE.md) and the [threat model](https://github.com/JuanenRac/HYDRA-UMC-DOCS/blob/main/docs/THREAT_MODEL.md) before relying on any statement here for the safety of a person.
