### Requisitos previos

* **Python 3.10 o superior** en el `PATH` (los scripts prueban `python3` y luego `python`).
* No hace falta todavía ninguna dependencia de runtime de seguridad/visión - **cero dependencias de terceros en tiempo de ejecución** en esta etapa (`dependencies = []` en `pyproject.toml`); `pytest` es un extra solo de desarrollo usado exclusivamente para la suite de tests real.
* Unas pocas decenas de MB de espacio en disco para un entorno virtual local en `.venv/`.

### Paso a paso

```bash
# Linux / macOS
./build.sh
```

1. **Lectura de la versión** - lee e imprime la versión del proyecto; compilar nunca la cambia (solo `python tools/hydra_project_tool.py bump` la sube).
2. **Entorno virtual** - crea `.venv/` si falta; lo reutiliza si ya existe.
3. **Instalación editable (con extras dev)** - `pip install -e ".[dev]"` para que los cambios en `src/` tengan efecto inmediato, instala `pytest`, y registra el entry point de consola `hydra-umc-safety-zones`.
4. **Compile-check** - `python -m compileall -q src` compila a bytecode cada archivo bajo `src/`.
5. **Suite de tests real** - `pytest tests/` ejecuta los {tests} tests.

`set -euo pipefail` detiene el script en el primer paso que falle; la ventana se queda abierta (`Press Enter to close...`) si se ejecutó con doble clic en vez de desde una terminal ya abierta.

```bash
./run.sh
```

Localiza el intérprete dentro de `.venv` y ejecuta `python -m hydra_umc_safety_zones.main`, reenviando cualquier argumento.

La invocación sin argumentos imprime nombre + versión + rol:

```text
HYDRA-UMC-SAFETY-ZONES v0.1.5
Real-time 3D intrusion detection and E-STOP orchestration for robotic safe-working areas.
```

El subcomando real `check` necesita un fichero de zonas y uno de detecciones, ambos JSON plano, más un fichero de estado de observación opcional. `calibration` es opcional en el fichero de zonas, y `--observation` es opcional en la línea de comandos - ver abajo qué pasa sin ellos:

```json
// zones.json
{
  "calibration": {"version": "cal-1", "source": "manual", "calibrated_at": "2024-01-15", "max_age_days": 30, "calibrated_by": "A. Operator"},
  "zones": [
    {"id": "warn1", "level": "warning", "min": {"x": 0, "y": 0, "z": 0}, "max": {"x": 5, "y": 5, "z": 5}},
    {"id": "danger1", "level": "danger", "min": {"x": 0, "y": 0, "z": 0}, "max": {"x": 1, "y": 1, "z": 1}}
  ]
}
```

```json
// detections.json
{"objects": [{"id": "op1", "position": {"x": 0.5, "y": 0.5, "z": 0.5}}]}
```

```json
// observation.json - evidencia real de que las detecciones de arriba
// realmente vinieron de un observador activo y actualizado recientemente
{"active": true, "observedAt": "2024-01-15T12:00:00Z", "maxAgeSeconds": 5}
```

Las fechas de estos ejemplos son solo ejemplos: `calibrated_at` debe ser lo bastante reciente para `max_age_days`, y `observedAt` debe estar dentro de `maxAgeSeconds` respecto a ahora (con zona horaria, por ejemplo una `Z` final); con las fechas mostradas, hoy el resultado es `INHIBITED`, no el `DANGER` de abajo.

```bash
./run.sh check --zones zones.json --detections detections.json --observation observation.json
```

```text
SAFETY STATE: DANGER - object(s) ['op1'] breached a danger zone
BREACH: object 'op1' inside warning zone 'warn1'
BREACH: object 'op1' inside danger zone 'danger1'
E-STOP REQUESTED: object 'op1' breached danger zone 'danger1' (not asserted - see estop.py)
```

Sale con `2` (Danger, E-STOP solicitado), `1` (brecha solo Warning), `0` (sin brecha, calibración válida, observador activo y fresco), o `3` (**Inhibited** - calibración ausente/caducada, u observador ausente/desactivado/caducado/con error, comprobado antes de cualquier lógica de brechas). Ejemplo real del camino de fallo seguro - las mismas `detections.json` de arriba, pero `zones.json` sin ninguna clave `"calibration"`:

```bash
./run.sh check --zones zones_no_calibration.json --detections detections.json --observation observation.json
```

```text
SAFETY STATE: INHIBITED - no calibration metadata present - zone geometry cannot be trusted
```

Sale con `3` - fíjate en que no hay salida `BREACH`/`E-STOP` en absoluto, aunque `op1` esté dentro de ambas zonas: un conjunto de zonas no fiable nunca llega al paso de comprobación de brechas. Omitir `--observation` por completo falla igual de seguro, incluso con calibración fresca y ningún objeto cerca de una zona:

```bash
./run.sh check --zones zones.json --detections detections_clear.json
```

```text
SAFETY STATE: INHIBITED - no observation status provided - cannot confirm the supplied detections reflect a real, active observer
```

La misma lógica de `check` también es accesible por HTTP, para clientes que no son la CLI - `zones`/`detections`/`observation` viajan en el cuerpo JSON en vez de una ruta de fichero:

```bash
./run.sh serve --addr 127.0.0.1 --port 8108
# en otra terminal:
curl -s -X POST http://127.0.0.1:8108/check -d '{"zones": {...}, "detections": {...}, "observation": {...}}'
```

Ver [`docs/CLI_REFERENCE.md`](docs/CLI_REFERENCE.md) para la referencia completa de comandos, flags y códigos de salida, incluyendo cada estado real (`READY`/`WARNING`/`DANGER`/`INHIBITED`) capturado de una ejecución real.

### Solución de problemas

* **No se encuentra `python`/`python3`** - instala Python 3.10+ y asegúrate de que está en el `PATH`.
* **`compileall` falla** - se introdujo un error de sintaxis real bajo `src/`; el build se detiene sin tocar la instalación, a propósito.
* **"No `.venv` found" en `run.sh`/`run.bat`** - ejecuta `build.sh`/`build.bat` al menos una vez antes.
* **Instalación editable desactualizada** - borra `.venv/` y reconstruye; rara vez hace falta.
* **`check` sale con código distinto de cero** - eso es comportamiento real y correcto, no un fallo: `1` significa que se encontró una brecha solo Warning, `2` significa que una brecha Danger solicitó un E-STOP, `3` significa que la calibración del conjunto de zonas está ausente/caducada o el estado del observador está ausente/desactivado/caducado/con error (fallo seguro, comprobado antes de que se ejecute cualquier lógica de brechas). Solo un traceback de Python o un error de JSON malformado es un fallo de verdad.
