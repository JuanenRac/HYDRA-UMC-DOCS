**HYDRA-UMC-MQTT-BROKER** は、HYDRA-UMC エコシステム向けの軽量な非同期
メッセージングインターフェースを提供します。外部の IoT デバイス、
ダッシュボード、ホームオートメーションシステム（Home Assistant など）
がロボットのテレメトリを購読し、コマンドを発行できるようにします。

MQTT 3.1.1 標準を実装しており(Aedes 経由、実機で検証済み - 下記アーキテクチャ参照)、最小限のオーバーヘッドで高効率なデータ
配信を提供します。モバイルアプリや低帯域幅のリモート監視に最適です。

### 主な機能：
* 🔌 **外部マシンブリッジ:** `HYDRA-UMC-BRIDGE-CNC`/`-LASER`/`-OPENPNP`/`-PRINTER3D`/`-ROS2` はそれぞれ、独自の `hydra/bridges/<name>/...` トピックを通じてこのブローカーに到達する —— `docs/BRIDGE_TOPICS.md` を参照。*(実装済み)*
* 📡 **パブリッシュ/サブスクライブ テレメトリ：** 関節角度、工具状態、システムの健全性のサブミリ秒単位の配信。（計画中：ロボットの状態はまだブローカーを通っていません。現在は工作機械ブリッジの `hydra/bridges/<name>/...` トピックのみです）
* 🛠️ **ディスカバリーサポート：** mDNS と Home Assistant 自動検出により、簡単にセットアップできます。*（計画中——まだ実装されていません。`src/server.ts` は現在ただの TCP リスナーであり、ディスカバリーサービスは一切ありません）*
* 🔐 **トピックセキュリティ：** 特定のロボットトピックの読み書きに対する、クライアント ID プレフィックスごとの実際に検証可能な ACL——ワイルドカードを使った SUBSCRIBE が、そのルールより広いアクセス権を得ることは決してありません。*(実装済み)*
* 🪪 **クライアント認証：** 任意の MQTT CONNECT ユーザー名/パスワード認証（`MQTT_AUTH_JSON`）により、ACL に検証済みのセッション ID を提供します——各認証情報自身が要求する `clientIdPrefix` も強制されるため、有効だが権限の低い認証情報が、より高い権限を持つ別のクライアント ID を単純に選んでその ACL 権限を継承することはできません。*(実装済み。ACL と組み合わせて使用)*
* 📏 **ペイロードサイズ制限：** PUBLISH のペイロードサイズに対する実際のオプトイン方式の上限で、`MAX_PAYLOAD_BYTES` で設定可能です。*(実装済み)*
* ⚡ **WebSocket サポート：** ブラウザベースのクライアント向けの MQTT over WebSocket——同じブローカーインスタンス上で、既存のプレーン TCP と並ぶ本物のオプトイン第2リスナー(`wsPort` オプション / `MQTT_WS_PORT` 環境変数、デフォルトポート 8083)。*（実装済み）*
* ⏳ **retained メッセージの有効期限：** retained メッセージ向けの本物のオプトイン TTL(`retainedTtlMs` オプション / `MQTT_RETAINED_TTL_MS` 環境変数)——制限より古い retained 状態は、以後すべての購読者に永久に配信され続けるのではなく、実際に消去される。*（実装済み）*
* 🛡️ **本番ポリシー：** 本番起動（Dockerfile が設定する `NODE_ENV=production`）では、`MQTT_AUTH_JSON` と `MQTT_ACL_JSON` がない場合、16 文字未満または例のパスワードの場合、すべての認証情報のプレフィックスを網羅する ACL ルールがない場合は起動を拒否します。`MQTT_ALLOW_ANONYMOUS=1` は、意図的にオープンなラボ用ブローカーであることを示します。ACL はクライアントが選んだクライアント ID ではなく、認証情報が証明した ID（その `clientIdPrefix`）で評価されます。`MQTT_RETAINED_TTL_MS` で別の指定がない限り、retained メッセージは 24 時間で期限切れになります。`MQTT_BIND_HOST` / `MQTT_METRICS_HOST` でリスナーがバインドするインターフェースを選べます。*（実装済み）*
* 🔐 **ループバック以外では TLS：** 平文の MQTT リスナーがこのマシンの外に開いていて（既定はすべてのインターフェース）TLS が設定されていない場合、本番起動は実行を拒否します。`MQTT_BIND_HOST` で `127.0.0.1` に束縛するか、TLS を設定するか、信頼できるネットワークを `MQTT_ALLOW_PLAINTEXT=1` で意図的に受け入れてください。ループバックにない平文リスナーについては、起動のたびに警告が出ます。*(実装済み)*
* 🔒 **TLS：** 実際に動作するオプションの TLS 上の MQTT（`MQTT_TLS_CERT` / `MQTT_TLS_KEY`、ポート 8883、`MQTT_WSS_PORT` による安全な WebSocket）と、オプションの相互 TLS（`MQTT_TLS_CA` と `MQTT_TLS_REQUIRE_CLIENT_CERT=1`）。*（実装済み）*
* 🧰 **ハッシュ化パスワード・証明書による識別・遅いクライアントへの制限(すべて任意):** `MQTT_AUTH_JSON` のパスワードは `scrypt$...` として保存できます(`npm run hash-password` で作成。平文パスワードも引き続き使え、ハッシュはイベントループの外で計算されます)。`MQTT_TLS_CERT_IDENTITY=1`(相互 TLS と併用)は、検証済みクライアント証明書の CN でクライアントを識別し(CN はクライアント ID の接頭辞である必要があります)、パスワードなしでその名前の ACL を適用します。`MQTT_CONNECT_TIMEOUT_MS`、`MQTT_KEEPALIVE_LIMIT_SECONDS`、`MQTT_QUEUE_LIMIT` は、接続が閉じられるまでにどれだけの時間・どれだけ貪欲に振る舞えるかを制限します。すべて既定では無効です。 *(実装済み)*
* 📊 **Prometheus メトリクス：** 実際に動作するオプションの `GET /metrics` リスナー（`metricsPort` オプション / `MQTT_METRICS_PORT` 環境変数、デフォルトポート 9883）が、接続クライアント数、受信メッセージ数、ACL 拒否数、入出力バイト数を報告します。*（実装済み）*
