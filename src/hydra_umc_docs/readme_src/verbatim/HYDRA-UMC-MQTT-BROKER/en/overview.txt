**HYDRA-UMC-MQTT-BROKER** provides a lightweight, asynchronous messaging interface for the HYDRA-UMC ecosystem. It allows external IoT devices, dashboards, and home automation systems (like Home Assistant) to subscribe to robot telemetry and publish commands.

It implements the MQTT 3.1.1 standard (via Aedes, verified live - see Architecture below), offering high-efficiency data distribution with minimal overhead, making it ideal for mobile apps or low-bandwidth remote monitoring.

### Key Features:
* 🔌 **External Machine Bridges:** `HYDRA-UMC-BRIDGE-CNC`/`-LASER`/`-OPENPNP`/`-PRINTER3D`/`-ROS2` each reach this broker over their own `hydra/bridges/<name>/...` topics - see `docs/BRIDGE_TOPICS.md`. *(implemented)*
* 📡 **Pub/Sub Telemetry:** Sub-millisecond distribution of joint angles, tool states, and system health. *(planned - robot state is not on the broker yet; today only the machine bridges' `hydra/bridges/<name>/...` topics are)*
* 🛠️ **Discovery Support:** mDNS and Home Assistant auto-discovery for easy setup. *(planned - not implemented yet; `src/server.ts` is a plain TCP listener today, no discovery service of any kind)*
* 🔐 **Topic Security:** Real, verifiable per-client-ID-prefix ACL for reading and writing specific robot topics - a wildcard SUBSCRIBE can never grant broader access than its rule. *(implemented)*
* 🪪 **Client Authentication:** Optional real MQTT username/password CONNECT authentication (`MQTT_AUTH_JSON`) gives the ACL a verified session identity - each credential's own required `clientIdPrefix` is enforced too, so a valid but lower-privilege credential cannot simply choose a different, more privileged client ID to inherit its ACL permissions. *(implemented; pair it with ACL)*
* 📏 **Payload Size Limit:** A real, opt-in cap on PUBLISH payload size, configurable via `MAX_PAYLOAD_BYTES`. *(implemented)*
* ⚡ **Websockets Support:** MQTT-over-WebSockets for browser-based clients - the same broker instance, a real opt-in second listener alongside the existing plain-TCP one (`wsPort` option / `MQTT_WS_PORT` env var, default port 8083). *(implemented)*
* ⏳ **Retained Message Expiry:** A real, opt-in TTL for retained messages (`retainedTtlMs` option / `MQTT_RETAINED_TTL_MS` env var) - a retained state older than the limit is actively cleared instead of being handed to every future subscriber forever. *(implemented)*
* 🛡️ **Production Policy:** A production start (`NODE_ENV=production`, which the Dockerfile sets) refuses to run without `MQTT_AUTH_JSON` and `MQTT_ACL_JSON`, with passwords of at least 16 characters that are not examples, and with an ACL rule that covers the prefix of every credential; `MQTT_ALLOW_ANONYMOUS=1` says on purpose that it is an open lab broker. The ACL is evaluated against the identity the credential proved (its own `clientIdPrefix`), not against the client ID the client chose; retained messages expire after 24 hours unless `MQTT_RETAINED_TTL_MS` says otherwise; `MQTT_BIND_HOST` / `MQTT_METRICS_HOST` pick the interface the listeners bind to. *(implemented)*
* 🔐 **TLS away from loopback:** a production start refuses to run when the plain MQTT listener is open beyond this machine (the default bind is every interface) and TLS is not configured; bind to `127.0.0.1` with `MQTT_BIND_HOST`, configure TLS, or accept a trusted network on purpose with `MQTT_ALLOW_PLAINTEXT=1`. Every start warns about a plain listener that is not on loopback. *(implemented)*
* 📊 **Prometheus Metrics:** Real, opt-in `GET /metrics` listener (`metricsPort` option / `MQTT_METRICS_PORT` env var, default port 9883) reporting connected clients, total messages received, and total bytes in/out in standard Prometheus exposition format. *(implemented)*
* 🔒 **TLS:** Real, opt-in MQTT over TLS (`MQTT_TLS_CERT` / `MQTT_TLS_KEY`, port 8883, plus secure WebSocket with `MQTT_WSS_PORT`) and optional mutual TLS (`MQTT_TLS_CA` with `MQTT_TLS_REQUIRE_CLIENT_CERT=1`). *(implemented)*
* 🧰 **Hashed passwords, certificate identity and slow-client limits (all optional):** a password in `MQTT_AUTH_JSON` may be stored as `scrypt$...` (write it with `npm run hash-password`; plain passwords keep working and the hash is derived off the event loop); `MQTT_TLS_CERT_IDENTITY=1` (with mutual TLS) identifies a client by the CN of its verified certificate, which must prefix its client ID, and applies the ACL of that name with no password; `MQTT_CONNECT_TIMEOUT_MS`, `MQTT_KEEPALIVE_LIMIT_SECONDS` and `MQTT_QUEUE_LIMIT` bound how long and how greedily a connection may behave before it is closed. All off by default. *(implemented)*
