> **诚实检查——今天真正可运行的部分：** 无依赖的协调核心（`coordinator.py` 中的 `Ros2Coordinator`，每次派发都会经过 `HYDRA-UMC-SDK` 自身真正的 `evaluate_job()`）、面向 `std_srvs/Trigger` 和 `std_msgs/String` 的真实（延迟导入的）`rclpy` 传输层（`rclpy_transport.py` 中的 `Ros2SafeStopClient`/`Ros2StateSubscriber`），以及 MQTT 命令/状态传输（`mqtt_transport.py`）都是真实的，并由 {tests} 个通过的单元测试覆盖（`python tools/build_test.py` —— `test_coordinator.py`、`test_rclpy_transport.py`、`test_mqtt_transport.py`）。以上这些都从未针对真实的 ROS 2 安装、真实的 DDS 网络或真实的 MQTT broker 进行过验证——`test_rclpy_transport.py` 是针对一个伪造的节点/发布者运行的，`test_mqtt_transport.py` 是针对一个伪造的 broker 客户端运行的，因此这些测试甚至不需要安装 `rclpy`/`std_srvs`/`std_msgs` 就能通过。自定义的 `.srv`/`.action` 契约 `inspect_service`/`job_action` 目前仍然没有真实的标准 ROS 2 消息类型，也完全没有客户端。详见下文的"当前状态与后续步骤"（已经如实说明了这一点），以及 `CHANGELOG.md` 中目前具体已交付的内容。


> **安全与安防现状:**本生态系统不是经认证的安全系统。目前尚无硬件 E-STOP 通路,没有由固件强制执行的限位或联锁,也没有经过验证的运动指令;固件映像使用 CRC-32 和 Ed25519 签名校验,发布构建会拒绝已公开的开发密钥(中继之后的工具头和扩展板仍运行 URTC 的引导程序,它们使用共享密钥的 HMAC-SHA256 而不是签名);TLS 与双向 TLS 均为可选项,默认关闭;自制电路板尚未组装或测试。在依赖此处任何说法来保障人身安全之前,请先阅读[安全基线](https://github.com/JuanenRac/HYDRA-UMC-DOCS/blob/main/docs/SECURITY_BASELINE.md)和[威胁模型](https://github.com/JuanenRac/HYDRA-UMC-DOCS/blob/main/docs/THREAT_MODEL.md)。
